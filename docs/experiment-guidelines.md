# PHY Lab 实验制作规范

本文汇总对话中已确认的项目要求，作为后续新实验和现有实验扩展的共同基线。当前实现是参考，不代表所有旧界面均已符合本规范；后续修改涉及的部分应按此验收。排期见 [实验制作顺序](experiment-roadmap.md)，视觉细节见 [DESIGN.md](../DESIGN.md)。

## 产品与支持范围

- 纯前端、可离线的物理实验平台，以“可操作的场景 + 同步数据 + 物理解释”帮助理解规律。
- 只面向桌面，窗口宽度至少 1280 CSS px；推荐 1440px 或更宽。窄窗口显示桌面尺寸提示，不设计移动端布局。
- 本次补充单屏验收尺寸：浏览器内容区推荐 1440×900，紧凑桌面基准为 1280×720，均按 100% 缩放检查。
- 每个实验是独立页面，通过插件接口内嵌工作台，持续保留平台顶栏。首页使用 Grid 卡片，包含缩略图、名称、简介与 Tags，并可搜索。
- 首页搜索在顶栏居中；左侧九点菜单默认收起，提供首页等链接；右侧提供语言、主题和设置。实验页可通过已有顶栏接口放置播放等控件。
- 项目以 Apache License 2.0 开源；第三方代码、素材和字体的来源、许可证与署名需保留。

## 技术栈与目录

- Bun 管理依赖、执行脚本与测试，Vite 8 构建，TypeScript 开发，Web Components 使用 Lit。
- 场景优先使用现有 SVG / Canvas 能力，公式使用现有 KaTeX。沿用当前工具，不因新增实验额外引入 UI、图表、物理引擎或应用框架；确有必要先说明具体收益并确认工具变更。
- 常规解析计算、少量微分方程积分和采样使用 TypeScript。仅复杂、耗时并经性能分析确认的计算考虑 Rust WASM，不能把“物理计算”等同于“必须 WASM”。
- 自定义开发、构建、预览、验证与发布脚本使用 `scripts/*.ts`，由 Bun 执行；`justfile` 提供统一命令入口。不增加平行的 JavaScript 或 Shell 构建脚本体系。
- 运行时不依赖服务端、外部 CDN、在线字体或第三方计算 API。实验所有必需资源纳入自身发布与离线清单。

```text
src/
  ui/
    components/             # 平台公开基础控件
    layouts/                # 工作台布局
    styles/                 # 主题与样式变量
  pages/                    # 路由页面
  infra/
    locales/                # 平台文案
    platform/               # 公开插件接口与目录接入
  services/                 # 设置、存储、主题、路由、离线与更新
experiments/
  <experiment-id>/
    experiment.json         # 实验元信息与独立版本
    index.ts                # mount 入口
    model/                  # 物理模型，独立于渲染
    components/
    styles/
    locales/                # 实验自身的中英文文案
    assets/                 # 缩略图与资源
    tests/
    wasm/                   # 仅需要时创建，Rust 源码与计算模块
scripts/                    # TypeScript 工具脚本
justfile
docs/
```

除插件协议要求的文件外，内部目录按需要建立，不创建空壳模块。实验不互相引用，不引入平台私有实现，不把实验业务放入全局 services；各实验的计算、WASM、样式、文案和素材保持自包含。接入细节见 [插件协议](plugin-contract.md)。

## 语言与文案

- 用户界面默认简体中文 `zh-CN`，完整支持英文 `en`，跟随平台切换。名称、简介、Tags、控件、说明、图例、单位解释、任务与错误反馈都要覆盖。
- 文案放在各自 locales 中，不在分散组件中长期维护两套硬编码文案；两个语言版本均需检查排版。
- 新增源码文件和标识符使用清楚的英文；开发说明以简体中文为主。物理符号沿用标准记法，数值与单位不因翻译改变含义。
- 操作词简短明确；说明跟随当前模型和画面。不把 Worker、WASM、构建路径等开发细节放入实验核心操作区。

## 视觉与主题

- 黑白为主体，蓝色为 Primary，少量用于焦点、选中态和主要操作。平台保持简洁，不用大面积装饰色、玻璃效果或装饰性渐变。
- 基础圆角与控件约 3px，卡片约 4px；保留极小圆角。使用细边框、系统无衬线字体、等宽数字和 8px 间距体系。
- 科学内容可使用柔和材质、局部微光、网格、参考轨迹与矢量增强表现；效果必须服务于观察物理过程，不能遮挡刻度、曲线或操作对象。
- 弹簧小球保持柔和蓝色、略微立体的球面质感，避免突兀的高光斑点。保持现有已确认的表现方向。
- 位移 / 势能用蓝色，速度 / 动能用绿色，加速度用红色。其他量定义稳定的图例；不得让新增量与既有语义混淆。曲线同时有名称、单位或线型，不能只靠颜色。
- 浅色、深色都使用平台 CSS tokens，穿过 Shadow DOM；主题切换使用 View Transition API，从点击位置圆形裁切展开。不支持或启用减少动态效果时直接切换。

## 单屏实验台

目标是在支持的桌面尺寸内，不上下滚动就能完成“调参 → 运行 → 暂停 / 回看 → 查看关键数据”的主要流程。

- 顶部保留工作台工具栏；中央主场景始终可见。默认采用左侧参数、中央场景与时间控制、右侧曲线与观察模式的三栏布局；有明确观察收益时可调整比例，不改成纵向长页面。
- 主参数、模式切换、播放 / 暂停、重置、慢放、时间游标、关键读数与当前图表应在一屏内可达，不能依赖页面或参数面板上下滚动。
- 内容增加时优先使用互斥的模式、参数分组标签、图表切换、就地替换或紧凑摘要；不能把更多曲线、解释和任务不断追加到下方。
- 当前公式与一句解释放入有限的固定区域；完整推导、帮助、探索任务详情和少用设置可通过标签、弹窗或设置入口展开。长说明允许在浮层内滚动，不影响主实验操作。
- 布局先预算顶栏、标题、场景、读数、曲线与控制区高度；使用有约束的 Grid / Flex 和正确的 `min-height: 0`。禁止单靠 `overflow: hidden` 或隐藏滚动条掩盖内容溢出，也不能把字号缩小到难以阅读。
- 关闭辅助图层、切换语言或观察模式，不得造成主场景跳动、控件移出视口或时间轴消失。场景与曲线必须保留足够面积，不用大量空白和冗长标题挤占实验空间。
- 在 1280×720、1440×900 和较宽桌面检查中英文与明暗主题。放大文字或低于目标高度时，允许提供可访问的滚动兜底，不能裁掉控件；这不代表常规尺寸下允许核心流程依赖滚动。
- 首页实验目录可以滚动浏览；单屏要求主要约束实验操作界面。

## 物理模型与数据一致性

- 先明确模型假设、变量、单位、适用范围和初始条件，再实现交互。视频和其他网站用于研究与参考，公式与结论需核对教材，不能照搬其中的演示错误。
- 模型与渲染分离。场景、轨迹、箭头、读数、曲线、游标、公式代入和能量条从同一个模拟状态 / 时间产生；慢放只改变时间推进速度。
- 数值积分不能直接依赖浏览器帧率；采用稳定步进或解析求值。时间回看必须可重现，不能让曲线与画面使用不同的近似结果。
- 不同单位采用分图或明确标注的归一化，显示单位、轴范围和缩放含义。箭头表示真实方向与大小关系；不同物理量的箭头长度不能直接比较。
- 特效轨迹必须来自真实模型采样。不得用任意 CSS 动画模拟物理结果，不得修改数值来迎合画面，也不能悄悄裁掉超量程数据。
- 公式、说明、模型条件与关键时刻应随物理模式变化。切换到有耗散或外力的模型后，不能继续宣称机械能恒定；非简谐运动不能照搬理想相位和周期。
- 覆盖零值、参数边界、退化情况和无效存档；避免 NaN、除零、虚假周期或不存在的关键时刻。计算超量程或模型不适用时明确说明。

## 交互与辅助图层

- 能直接操作场景时优先提供拖动，配套键盘等价操作；调参明确标注名称、当前值、范围与单位。主按钮通常至少 36px 高，焦点清晰可见。
- 提供播放、暂停、重置、慢放和时间回看；关键时刻可直接定位，并说明此时的物理含义。参数变化的重启 / 对比规则须明确且一致。
- 观察模式只改变观察内容；辅助图层开关只改变可见性，不重置时间、参数或播放状态，不因显示开关重新缩放场景。只在模型适用时展示该辅助图。
- 弹簧的旋转矢量可隐藏，沿用已确认的球体质感；理想模式中圆心与平衡位置一致，矢量端点的水平投影准确对应球心。具体约定见 [弹簧模型](spring-model.md)。
- 隐藏控件退出焦点顺序；弹窗支持 Escape，关闭后恢复焦点；实时数值不连续触发屏幕阅读器公告。兼容减少动态效果偏好。
- 页面隐藏、离开实验或释放实例时正确暂停、保存并清理动画与监听器，不在后台持续推进用户无法观察的实验。

## 状态、版本、离线与更新

- 设置、实验参数、观察模式、图层偏好和必要的暂停状态持久化到 LocalStorage；实验通过 `context.storage` 访问隔离存储，不自行覆盖平台或其他实验的键。
- 恢复状态前校验范围、有限值与结构。新增字段提供默认值；有状态格式变化时独立维护 `stateVersion` 并迁移旧数据，失败时保留可恢复数据。
- 平台版本的唯一来源是根 `package.json`，当前 0.1.0；实验版本只在自己的 `experiment.json` 维护。平台与实验不锁步升级，新增实验不要求更新平台。
- 协议版本、状态版本和内容构建指纹各自独立。文案、样式和资源变化也须遵循不可变发布约定，不覆盖已经发布的构建地址。
- Service Worker 缓存平台与当前目录中兼容实验的必需资源，完整校验后才声明可离线使用；首次完整缓存后应能断网打开尚未进入过的实验。Worker 元信息与资源使用 Cache Storage，不使用 LocalStorage。
- 平台更新先准备资源，保存状态后由用户启用；实验更新独立准备，正在运行的实例固定原构建，下次进入使用就绪版本。失败继续使用完整旧版本。
- 开发环境不注册生产缓存；Service Worker、JS、WASM 必须返回正确的 MIME，资源错误不能回退成 HTML。细节见 [发布、离线与更新](release-and-update.md)。

## 完成标准与提交

1. 暂停在任意时刻，能看清对象状态、运动方向、受力 / 加速度与能量分配中适用于当前模型的内容。
2. 主要操作和数据在桌面单屏中可用；中英文、明暗主题、鼠标、键盘与减少动态效果均检查。
3. 用有物理意义的测试验证守恒关系或能量收支、典型解、参数边界与时间回看；不写只重复实现细节的测试。
4. 涉及的旧存档、状态恢复、离线加载与独立发布流程验证通过；影响资源或更新机制时补做生产预览验收。
5. 按 [贡献指南](../CONTRIBUTING.md) 运行适用检查，更新使用说明、模型文档和路线状态；文档中区分计划与已完成行为。
6. 每完成一个可独立验证的功能提交一个 commit，使用 `feat:`、`fix:`、`docs:`、`test:` 或 `chore:` 前缀，不把多个无关功能混在一起。
